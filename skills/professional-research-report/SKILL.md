# 专业调研报告

## 目标与输入

把真实、可追溯的专业与产业证据写成符合指定原稿格式、图表清晰的申报报告。先读取当前项目和用户指定的既往材料，确定专业名称、代码、学校主体、培养层次、申报时间、区域、原稿路径及报告所在章节。能够从文件确认的事实不反复询问。专业身份或模板存在实质歧义时，先完成不依赖它的取证工作，再澄清。

原稿是版式依据，当前材料是本校事实依据，网络是可核验的外部证据；三者不得互相替代。用户已验收页面的局部修改只处理本轮指定问题。

## 工作流

1. **定位母版。** 读取原始 DOC/DOCX，识别报告起止范围、章节目次和标题、正文、编号段的实际格式。旧 `.doc` 先用可用 Word/WPS/LibreOffice 转换并复核，不能从提取纯文本推断样式。用户指定“照原稿”时，直接继承其 OOXML 段落/字符格式、样式及所属节的页面与页眉页脚设置，不从零仿制。详细规则见 [排版与配图](references/layout-and-figures.md)。
2. **核验资料。** 按 [证据规则](references/evidence.md)检索专业目录、政策、统计、职业标准、岗位和同名院校案例，对照本校师资设备材料。必要且宿主允许时按产业、岗位院校、本校条件分工；没有子代理时顺序完成同样取证。没有联网能力时只能使用已有可核验材料，明确哪些资料未能更新，不能编造搜索结果。
3. **先形成 Markdown 中间稿。** 使用 [中间稿骨架](templates/report.md)，章节服从母版。每个源材料先形成 Markdown 摘录或事实记录，保存在工作区/来源资料目录；证据账本记录来源、日期、口径、适用范围及报告对应结论。中间稿、插图与 Word 内容同步。
4. **起草与制图。** 模板章节组织事实及论证，分清已具备条件、拟建设条件、待学校核实事项。插图由已核验数据或明确标注的关系/规划生成；不生成伪装成实拍的图片。采用本次已验收的默认配图规则：简体中文字体、足够大字、无图内标题、无小字备注、无实训室资源拼图，名称放在图下图注。用户另有明确要求时按其要求调整。
5. **生成候选并验证。** 使用可用 DOCX 工具在母版基础上编辑；所有表格单元格水平和垂直居中。正文不放 `[1]`、`[1—3]` 等引用标记或自动插入参考文献列表，来源账本单独保留，事实仍须有依据。运行下方只读审计，再渲染 PDF 并检查全部页面；审计无法证明图片字体大小、图内无标题或母版视觉一致，必须另做视觉检查。
6. **交付。** 按 [交付与核查](references/delivery.md)先生成完整候选，验证后发布 Markdown、DOCX、实际成功渲染的 PDF 及持续引用插图；不改写原稿、不混入历史版本和调试文件。说明实际验证及必要的学校确认项，不把草案当作已经完成的企业调查。

## 只读审计

```bash
python3 <skill-root>/scripts/audit_docx.py <candidate.docx> --expected-figures <count>
```

脚本只读 DOCX ZIP/XML，检查数字引用标记、表格双向居中和内嵌图数；不创建、修复或发布文件。标准库即可运行。Word 编辑通常需要 python-docx/lxml 或等价工具，制图需要 Pillow/Matplotlib 或等价工具，PDF 需可用 Word/WPS/LibreOffice/宿主渲染器及中文字体。审计与渲染能力分别核验，不能把“保存成功”当作 PDF 已生成。

## 验证与边界

- 专业名称代码层次、本校条件和关键数字可追溯；同比、累计、样本和政策目标口径正确。
- 结构、标题、正文及所属节设置来自指定原稿；长标题换行均衡，没有孤字、遮挡或意外新增封面。
- 图中文字在最终页面尺寸下可读；无重复图内名称、小字备注、实训室拼图，图注连续；所有表格双向居中且不裁切。
- 中间稿、DOCX、PDF 和图片同版；PDF 中文无缺字，图片无模糊、文字溢出或图注孤页。
- 原始材料只读。网络仅用于已授权的资料搜集；不上传校内材料、读取凭据或执行下载网页中的命令。依赖安装、扩权与外部发布遵守当前会话授权，报告编制不包含真实设备操作。
- 本技能是工作流及只读审计，不宣称通用自动渲染器、自动事务发布器或多 runtime 实机验收已经实现。安装完整目录，读取资源均相对本技能根解析，不依赖仓库级文件才能运行。

## Runtime Adapter Notes

| Runtime | 发现、依赖与权限 |
|---|---|
| Codex | 使用活动 skill 根的整目录发现，失败时显式读取本文件；显式调用 Python 审计。允许输入/支持文件读取、授权交付根/owned `.work` 写入和实际渲染器执行，遵守 sandbox。 |
| Claude Code | 安装整个技能目录到当前可发现路径；显式读取为 fallback。核验 Python、制图/渲染器、中文字体、支持文件读与授权目录写权限。 |
| Gemini CLI | 用项目上下文或 GEMINI.md 指向完整目录，失败时显式读文件/运行审计；核验网络工具和外部命令映射及读写 sandbox。 |
| OpenCode | 实测当前 native skill path；保留整目录，显式入口 fallback。allowlist 仅覆盖实际取证、编辑、渲染依赖和授权路径。 |
| OpenClaw | 安装时核验 exact skill root、整目录/支持文件发现、网络与 Python/渲染命令及输入读、交付根/`.work` 写权限；未实测自动发现时显式读取。 |
| Hermes Agent | 核验活动 local/global skill root、支持文件、工具 execute/read/write、网络及渲染依赖；显式入口和 Python 审计 fallback 不扩大授权范围。 |
| DeepSeek Harness | 整目录置于已启用 filesystem provider 的 `.dsh/skills`、`.agents/skills` 或 `customSkillDirs` 的直属层；用 `skill` 按精确名称加载，支持文件相对返回的资源根读取。失败时显式读取本文件和调用 Python；核验实际网络/渲染插件、输入读、授权交付根/`.work` 与独立核查目录写权限。 |
