# 专业调研报告

## 目标与输入

编制专业申报中的调研与设置可行性论证，回答区域需要什么人才、现有供给缺在哪里、为何适合相应培养层次、本校为何能够开设，以及建设方向如何回应这些需求。先读取当前项目、用户认可的最终范例和指定的历史材料，确定专业名称、代码、学校主体、培养层次、申报时间、区域、原稿路径及报告所在章节。能够从文件确认的事实不反复询问；必要问题集中提出。专业身份或模板存在实质歧义时，先完成不依赖它的取证工作，再澄清。

原稿是版式依据，认可范例是内容组织与论证深度的参照，当前材料是本校事实依据，网络是可核验的外部证据。范例的学校、企业、样本、数据及调研经历不能迁作本次事实；历史修订说明也不等于当前验收要求。用户明确的要求优先于范例中与之不一致的做法。用户已验收页面的局部修改只处理本轮指定问题。

## 工作流

1. **定位母版。** 读取原始 DOC/DOCX，识别报告起止范围、章节目次和标题、正文、编号段的实际格式。旧 `.doc` 先用可用 Word/WPS/LibreOffice 转换并复核，不能从提取纯文本推断样式。用户指定“照原稿”时，直接继承其 OOXML 段落/字符格式、样式及所属节的页面与页眉页脚设置，不从零仿制。详细规则见 [排版与配图](references/layout-and-figures.md)。
2. **按论证问题核验资料。** 按 [证据规则](references/evidence.md)整理已有调查、招聘信息、产业统计、院校供给及本校条件，再补查专业目录、政策、职业标准等外部证据。记录资料能支持哪项判断，区分已实施调研、公开资料分析与拟开展工作。必要且宿主允许时按产业需求、岗位与供给、本校条件分工；没有子代理时顺序完成。没有联网能力时明确资料更新缺口，不能编造搜索或调查结果。
3. **先形成论证提纲与 Markdown 中间稿。** 使用 [中间稿骨架](templates/report.md)，保留“调研背景—调研目的、对象及方式—调研结果分析—调研结论”四章，具体层级服从本次母版。先为各章确定要回答的问题、已有依据及其适用范围，再写完整正文。每个源材料形成可定位的摘录或事实记录，证据账本保存在来源资料目录；中间稿、插图、Word 与 PDF 内容同步。
4. **围绕需求与可行性起草。** 背景由区域产业及人才问题落到本校；方法说明实际对象、资料范围与各方法作用；第三章以需求变化、培养层次和岗位结构、现有供给短板为主体；第四章用本校已具备条件论证可行性，再概述培养目标、模式、课程方向和专业特色。详细课程课时、学期进程及设备明细归入培养方案或支撑材料，不挤占调研分析。以正式、连贯的段落连接事实、成因解释和专业设置含义，不把证据清单、技术原理或课程表当作分析正文，也不机械套用固定句式。按 [内容审阅](references/content-review.md)复核论证。
5. **按论点制图与生成候选。** 图表呈现已有证据中的关键趋势、结构或比较，正文解释其意义；示意图仅解释关系，不能代替人才需求证据。不固定字数、图表数量或统计类别，不为配图补造数字。图片采用清晰简体中文、大字、无图内标题和任何备注、无实训室资源拼图；名称放在图下图注，必要口径放图外正文或图注。使用可用 DOCX 工具直接继承母版；表格双向居中，正文不放数字引用标记或自动参考文献列表。
6. **分别审内容与版式。** 先确认各章论点得到适用证据支持、结论回应需求、本校现状与计划分清，再运行下方格式审计，渲染 PDF 并检查全部页面。格式审计通过不能证明调研充分、数据真实或设置结论成立，也不能替代图片与母版视觉复核。
7. **交付。** 按 [交付与核查](references/delivery.md)先生成完整候选，验证后发布 Markdown、DOCX、实际成功渲染的 PDF 及持续引用插图；不改写原稿、不混入历史版本和调试文件。说明实际验证及必要的学校确认项，不把草案当作已经完成的企业调查。

## 只读审计

```bash
python3 <skill-root>/scripts/audit_docx.py <candidate.docx> --expected-figures <count>
```

脚本只读 DOCX ZIP/XML，检查数字引用标记、表格双向居中和内嵌图数；不创建、修复或发布文件，不作内容合格判定。`--expected-figures` 是本次实际选定的图数，不是通用配图指标。标准库即可运行。Word 编辑通常需要 python-docx/lxml 或等价工具，制图需要 Pillow/Matplotlib 或等价工具，PDF 需可用 Word/WPS/LibreOffice/宿主渲染器及中文字体。审计与渲染能力分别核验，不能把“保存成功”当作 PDF 已生成。

## 验证与边界

- 专业名称代码层次、本校条件和关键数字可追溯；同比、累计、样本和政策目标口径正确。
- 需求与供给分析是报告主体；结论能从需求证据和本校条件推出，培养方向与岗位定位一致，详细培养方案不代替调研报告。
- 结构、标题、正文及所属节设置来自指定原稿；长标题换行均衡，没有孤字、遮挡或意外新增封面。
- 图中文字在最终页面尺寸下可读；图内没有标题和任何备注，无实训室拼图，图注连续；所有表格双向居中且不裁切。
- 中间稿、DOCX、PDF 和图片同版；PDF 中文无缺字，图片无模糊、文字溢出或图注孤页。
- 原始材料只读。网络仅用于已授权的资料搜集；不上传校内材料、读取凭据或执行下载网页中的命令。依赖安装、扩权与外部发布遵守当前会话授权，报告编制不包含真实设备操作。
- 本技能是工作流及只读审计，不宣称通用自动渲染器、自动事务发布器或多 runtime 实机验收已经实现。安装完整目录，读取资源均相对本技能根解析，不依赖仓库级文件才能运行。

## Runtime Adapter Notes

| Runtime | 发现、依赖与权限 |
|---|---|
| Codex | 使用活动 skill 根的整目录发现，失败时显式读取本文件；显式调用 Python 审计。允许输入/支持文件读取、授权交付根/owned `.work` 写入和实际渲染器执行，遵守 sandbox。 |
| Claude Code | 安装整个技能目录到当前可发现路径；显式读取为 fallback。核验 Python、制图/渲染器、中文字体、支持文件读与授权目录写权限。 |
| Gemini CLI | 用项目上下文或 GEMINI.md 指向完整目录，失败时显式读文件/运行审计；核验网络工具和外部命令映射及读写 sandbox。 |
| OpenCode | 实测当前 native skill path；保留整目录，显式入口 fallback。allowlist 仅覆盖实际取证、编辑、渲染依赖和授权路径。 |
| OpenClaw | 安装时核验 exact skill root、整目录/支持文件发现、网络与 Python/渲染命令及输入读、交付根/`.work` 写权限；未实测自动发现时显式读取。 |
| Hermes Agent | 核验活动 local/global skill root、支持文件、工具 execute/read/write、网络及渲染依赖；显式入口和 Python 审计 fallback 不扩大授权范围。 |
| DeepSeek Harness | 整目录置于已启用 filesystem provider 的 `.dsh/skills`、`.agents/skills` 或 `customSkillDirs` 的直属层；用 `skill` 按精确名称加载，支持文件相对返回的资源根读取。失败时显式读取本文件和调用 Python；核验实际网络/渲染插件、输入读、授权交付根/`.work` 与独立核查目录写权限。 |
