# 交付与检查

先在本次授权交付根的 `.work/<run-id>/candidate/` 形成完整候选，通过 [内容复核](content-review.md)、DOCX 格式审计与 PDF 全页检查后再发布。三项检查分别记录：格式审计通过不能代替论证或数据核验，PDF 可打开不能代替页面检查。原模板与取证资料只读；真实学校原稿、报告及企业材料不放入技能仓库。

默认显式 current 集合为 `专业调研报告.md`、`专业调研报告.docx`、`专业调研报告.pdf`；没有可用 PDF 渲染器时不产生虚假 PDF，也不宣称完整交付，明确只交付已验证格式。用户指定其他名称时先固定同一 stem 的准确集合，不用 glob/后缀推断覆盖目标。可选 PDF 的增减也要纳入集合比较。

- `assets/` 只放当前 Markdown 持续引用的、明确登记的插图，实际图数与文件名在发布前固定，和 current 同版维护；删除一张图后图号、图注和正文引用都要同步。
- `sources/` 放输入资料、格式定位记录、证据账本和学校待核实事项，普通发布不改写已有原始资料，也不随版本自动归档。新研究记录使用独立文件，不能覆盖旧证据。
- `history/<max+1>/` 保存旧版完整 current 组和旧版引用的插图；不得把 V1/V2/预览截图平铺在交付根。path-set 和字节都相同则 no-op，不新建历史。
- 日志、渲染分页图、审计报告、缓存仅在本次 owned `.work` 或用户另指定的核查目录；不把它们作为最终报告交付。
- 发布前核对准确目标及其父路径，无符号链接、特殊文件、路径穿越、未知/混杂/不完整旧版；有歧义时不整理未知文件，先保留现场并解决明确归属。只处理本次声明的文件。
- 候选完整验证前不触碰 current。更新先备份并核对旧组、再整组归档及逐路径发布，若可处理的异常发生则恢复旧组并只清理本次拥有的 work/未完成历史。不承诺多文件硬原子、断电或 SIGKILL 回滚；没有可靠发布器时由调用 agent 显式执行和核对这些动作。

本技能不携带自动 renderer/publisher，不新增仓库既有六技能的自动 clean-delivery 验收覆盖。实际运行需核对可用编辑/渲染工具，结构检查通过不等于视觉验收通过。
