# 学生证明

1. 核对用户提供的系部、班级、姓名、学号、证明事项和出具部门。这六项均为必填。缺失、空白或使用模板占位时，一次列出需要补充的字段，补齐后再生成 DOCX 和 PDF。复制 [Markdown 模板](templates/学生证明.md) 到任务目录，将核实后的信息写入 YAML。学号按用户提供的原值填写，允许英文字母和数字。证明事项写成可承接在「同学（学号：…）」之后的动词短语，例如「在某培训中担任志愿者」或「参加某校内活动」。出具日期优先采用用户指定日期，未指定时将北京时间当天的中文公历日期写入 YAML。直接运行脚本时，缺省或留空的出具日期也使用北京时间当天。
2. 在生成成品前撰写结语，作为 YAML 区块下方唯一一行纯文本。
   - 把正面评价写成一句完整、自然的证明用语。先结合活动和学生角色写服务态度或参与表现，再写该角色对活动的支持。用分句把评价与活动联系起来，避免堆叠褒义词或重复首句。用户未提供评价时，采用与角色相符的适度措辞。培训志愿服务可写「该生在培训期间以积极主动的态度参与志愿服务，认真对待服务工作，为本次培训提供了支持。」
   - 用户提供评价时，保留其含义和程度，结合活动改写成流畅的完整句。有具体事例时，用最能体现评价的事实来支撑；具体职责、时长、获奖和成效以用户提供的材料为依据。
   - 标题、首句和落款由脚本排版，姓名加下划线，正文、部门和日期使用仿宋，右侧保留盖章空间。
3. 使用安装了 PyYAML、python-docx 的 Python 和可用的 Typst 执行 `python scripts/render.py <学生证明.md>`。命令从同一份 Markdown 生成同目录下同名的 DOCX 和 PDF。需要修改事实或措辞时，更新 Markdown 并重新生成。交付前核对文字、日期、字体、单页版式和落款位置。

## Runtime Adapter Notes

在 Codex、Claude Code、Gemini CLI、OpenCode、OpenClaw、Hermes Agent 和 DeepSeek Harness 中都应安装完整技能目录。用运行环境许可的终端执行脚本。OpenClaw、Hermes Agent 和 DeepSeek Harness 应先确认技能发现目录已登记，并在允许写入的任务目录中准备 Markdown。技能目录仅需读取。渲染机须具备所需 Python 依赖、Typst、STFangsong 和 Songti SC 字体。

脚本只读取指定源文件及技能内的版式，并写入相邻的两个同名成品。学生源稿及成品留在任务目录。用虚构数据验证脚本时，检查 PDF 页数及两个成品中的姓名、学号、结语和落款。
