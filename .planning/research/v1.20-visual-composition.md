# v1.20 视觉构图与媒体层调研

**范围：** `skills/school-pptx` 对照 `/Users/mrered/Developer/tools/ppt-master-core`  
**调研日期：** 2026-07-23  
**结论置信度：** 高（以两个本地实现与契约为证；尚未制作 v1.20 样张）

## 结论

`school-pptx` 不应接入或替换为 PPT Master 的自由 SVG/联网图片工作流。应吸收其“图片承载场景、原生形状承载可编辑信息”的两层构图原则，并将其收敛为 `standard-school` manifest、冻结的 `PhysicalDeckPlan` 和 emitter 所拥有的有限语义布局。这样能明显增加图文层次，同时不改变学校主题的颜色、字体、标题、页脚、结束页或 Markdown-first 事实边界。

当前实现并非从零开始：`image-text` 已有受控图片槽，`gallery` 已有按数量选择的卡片预设，`timeline` 用原生轴、节点和文本组，`table` 输出 PowerPoint 原生表格；图片也已经以 `contain`、无裁剪的方式写入 PPTX。因此 v1.20 的价值在于增加“媒体与可编辑证据层如何组合”的 renderer-owned 计划，而不是增加 Markdown 样式语法或整页位图。

## 必须冻结的边界

- 保持唯一主题 `standard-school`；不得重定义其颜色、字体、标题、页脚、装饰资产和 closing 页。
- Markdown 只表达既有逻辑内容、布局和本地媒体引用；禁止新增坐标、尺寸、裁剪、字体、颜色、背景、动画或任意 style 属性。
- 继续只接受本地、已验证的媒体；保持缺失媒体为非零结果且可编辑占位符的现有行为。不得引入网页抓图、在线搜图、AI 图片生成或运行时下载。
- 图片只承担场景、设备、课堂或成果证据；所有结论、数字、图注、步骤、标签、连接线、表格和图表必须是可在 PowerPoint/WPS 内编辑的原生对象。
- 保持分页在 emitter 前冻结，且 emitter 只能消费计划，不能在输出阶段临时选择构图或重新测量分页。

## 推荐的受控构图集合

以下名称是 renderer/manifest 内部语义，不是 Markdown 的样式参数；是否使用以及坐标均由 `VisualPlan` 根据既有 layout、媒体数量和冻结的 slot 预算决定。

| 模式 | 适合内容 | 固定构图与媒体职责 | 原生可编辑信息层 | 实施建议 |
|---|---|---|---|---|
| `hero-evidence` | 设备、实训现场、作品或课程成果的单一主证据 | 一张主图占主要视觉面积，文本落在模板保留的清晰阅读区；主图不写入事实文字 | 结论标题、2–3 个 KPI、短说明或来源图注 | 作为 `image-text` 的受控变体，仍使用本地图片与 `contain`；不采用 PPT Master 的 full-bleed/slice 裁剪。 |
| `annotated-image` | 需要指认设备部件、流程位置或操作要点的照片/截图 | 一张证据图为底，少量锚点和引线从图外信息区指向图中区域 | 编号圆点、引线、短标签和结论卡片 | 新增受限的“注释清单”逻辑数据只能由现有结构化内容派生；若 Markdown 无法无歧义表达，先不要公开该布局。 |
| `process-overlay` | 把场景/成品图与实施步骤关联 | 媒体提供真实场景，3–5 个步骤节点置于预留区域或半透明安全面板上 | 原生圆角卡片、箭头/线、序号、步骤文本 | 优先基于现有 `timeline` 的原生节点和 manifest subregions 扩展，而不是把流程图烘焙进图片。 |
| `kpi-evidence` | 实训条件、建设成效、课程数据或验收结论 | 单图或小图组作为证据，不与数值竞争；指标区保持规则栅格 | 原生数字卡、进度条、迷你表、结论标签 | 先限定 2、3、4 个指标的静态预设，所有数据文本来自冻结 plan；不要引入任意 SVG 图表。 |
| `evidence-gallery` | 多张设备、学生作品、场地或过程照片 | 1 张时给主证据更大面积；2–4 张使用受控视觉节奏和一致 caption 带 | 每张图片的原生图注、编号与可选统一说明 | 重做 `gallery.item_presets`，按图片数量使用已定义几何，而不是让 Markdown 决定拼贴位置。 |

`hero-evidence`、`annotated-image`、`process-overlay`、`kpi-evidence` 应先成为仓库外六页样张的四种构图基线；样张被视觉审阅接受后，才进入 manifest、物理计划和 emitter。`evidence-gallery` 可以在同一阶段作为现有 `gallery` 的低风险改良项。

## 建议的内部数据边界

```text
reviewed Markdown
  -> canonical logical document
  -> frozen PhysicalDeckPlan
       -> renderer-owned VisualPlan（布局角色、媒体数量、预设 ID、原生层清单）
         -> native PPTX picture + text + shape + table/group objects
```

`VisualPlan` 应是 `PhysicalDeckPlan` 的不可变、可投影字段或其确定性派生物，只记录诸如 `composition=hero-evidence`、`media_role=primary`、`overlay=kpi-3`、`preset=gallery-3-featured`。它不得记录 Markdown 提供的坐标、字体、颜色或裁剪，也不得作为公开 delivery sidecar。由它集中做“图像层 / 信息层”选择，避免 `pptx_emit.py` 出现基于内容临时分支的不可复验排版。

## 明确不吸收的 PPT Master 能力

| 能力 | 不吸收原因 | school-pptx 对应做法 |
|---|---|---|
| SVG 作为主页面中间格式、自由 path/preset 组合 | 会绕过受控模板与既有 python-pptx 发射、增加字体/浏览器渲染差异 | 仅使用 manifest 驱动的 python-pptx 原生文本、图片、形状和表格。 |
| 网页搜图、下载、AI 生成图片及自由图标库 | 与离线、可复验、本地媒体路径和安全边界相冲突 | 作者提供已审阅的本地媒体；缺失即失败或 best-effort。 |
| `slice` 裁剪、复杂滤镜、蒙版、玻璃拟态等视觉效果 | 破坏 D-13 的 contain 契约，且跨 PowerPoint/WPS 的可视结果不稳定 | 只允许稳定图片框、模板已有装饰和少量原生形状。 |
| 动画、转场、音频叙述 | 当前 school-pptx 明确 `transition_mode: none`，Markdown 也禁止动画语义 | 保持无动画；以后若另开范围，必须独立契约和 UAT。 |
| PPT Master 的直接 OOXML 追加式增强路线 | 该路线以保留已完成 deck 为目标，并不解决受控 logical→physical 渲染 | 继续由 school-pptx renderer 作为唯一输出所有者。 |

## 分阶段建议

1. **样张与视觉合同**：在仓库外以真实本地媒体做 6 页样张，覆盖四个新构图、一个改良 gallery 和一个现有基准页；冻结每种模式的视觉目的、可编辑对象清单与边界。
2. **模板/计划层**：只在 `standard-school` manifest 增加受控 subregion、静态 preset 和 `VisualPlan` 投影；扩展 parser 前先证明现有逻辑结构不足以消除语义歧义。
3. **发射与回归**：让 emitter 从 frozen plan 创建图片、文本、形状和表格；复用受限媒体读取与确定性分页，不新开运行时媒体通道。
4. **结构与真人 UAT**：同时验证 OOXML 原生对象、基准 fixture 不漂移，以及 PowerPoint/WPS 的构图、清晰度、可编辑性和主题一致性。

## 风险与缓解

| 风险 | 后果 | 缓解 |
|---|---|---|
| 为了“更好看”把文字、数字或流程烘焙进图片 | 不能编辑，中文内容和事实改动需重做图片 | 把图片限定为氛围/证据；所有信息层由 `add_rich_text`、shape、table 或原生 connector 生成。 |
| 让 Markdown 指定图层、坐标、颜色或裁剪 | 主题漂移，内容审阅与视觉审阅耦合，分页不可控 | 维持 D-15 allowlist；构图在 manifest + `VisualPlan` 内部决定。 |
| 直接复制 PPT Master SVG、滤镜或 chart asset | 复杂效果在 Office/WPS 不一致，或退化为不可编辑图片 | 只迁移构图意图；在 school-pptx 中以少量原生对象重建。 |
| 过度叠加注释/KPI/箭头遮挡教学证据 | 页面比原先丰富但阅读路径混乱 | 每页只允许一个主证据和一个信息层；每种 preset 固定最多 3 个 KPI、5 个步骤或 4 张图库图。 |
| 强行改变媒体裁剪策略 | 破坏已承诺的图片不裁剪契约，关键设备/文字可能被截断 | 所有新模式沿用 contain；若视觉上有留白，用模板拥有的卡片/底板承接，不裁剪源图。 |
| 只做结构测试而没有实际幻灯片检查 | PPTX 可打开却在真实 viewer 中层级、字体、阴影或组编辑异常 | 沿用 hash 绑定的 PowerPoint/WPS UAT，并增加本里程碑的视觉与对象编辑检查。 |

## 可验证验收点

### 自动验收

- `standard-school` 的既有 token、标题/页脚/closing 页、Markdown allowlist 与 `transition_mode: none` 维持不变；现有 fixture 的非视觉逻辑→物理分页映射不因新增模式改变。
- 每个新增构图在 manifest 中有唯一、完整、正尺寸的 subregion/preset；`template-report` 和 manifest 验证均通过。
- 相同 reviewed Markdown、媒体字节和 manifest 连续两次生成相同 `VisualPlan` 投影和相同对象角色/顺序；emitter 不重新选择构图或分页。
- 新模式的生成 PPTX 重新打开后，可检查到独立的 `p:pic`、`p:sp`、`p:grpSp` 和需要时的 `a:tbl`；禁止把整张页或信息层作为单一截图插入。
- 缺失、不可读、超像素或格式非法的媒体继续触发现有稳定错误/可编辑占位符及非零状态；不得回退联网资源。
- 图集、时间线、KPI/注释中的每一段文字都能从 logical/frozen plan 回溯；没有 renderer 自造事实、数字或图中文字。

### PowerPoint/WPS 人工 UAT

- 在同一台已记录版本的 PowerPoint 或 WPS 中，逐页检查主图清晰、无拉伸、无裁剪关键内容、图文对比足够，且没有遮挡标题、页脚或关闭页。
- 选择并编辑一条图注、一张 KPI 卡、一个流程节点/引线、一个时间线节点和一张原生表格；保存重开后这些对象仍独立存在、可编辑且不破版。
- 视觉审阅六页样张：每页只有一个清晰阅读主路径；主图、说明和可编辑信息层具有层级而不是把文本堆在图片旁或压在图片上。
- 与 v1.17 基准 deck 并排检查：学校蓝绿主题、字体、标题、页脚和结束页完全保持 `standard-school` 主体风格；新增视觉变化只发生在受控内容区。

## 未决问题

- `annotated-image` 的作者可表达语义尚未确定：若现有 Markdown 无法提供稳定的“标注文本—目标”关联，应延后该模式，不能以自由 attributes 破坏契约。
- 现有 `image-text` 的 contain 策略与“沉浸式主图”之间存在视觉取舍；本调研建议不改契约，最终以六页样张确认模板底板是否足以吸收留白。
- PPT Master 本地源码已可作为构图参考，但旧调研记录其完整依赖安装未验证；本结论不依赖运行或嵌入该工具。
