# v1.20 渲染架构调研：受控视觉增强

**范围：** `skills/school-pptx` 的 Markdown 契约、`standard-school` manifest、逻辑/物理计划、PPTX 发射及验证链路。  
**调研日期：** 2026-07-23  
**置信度：** HIGH（结论均由当前仓库实现与契约交叉确认）

## 结论

v1.20 应当是对既有 **语义→冻结 PhysicalDeckPlan→机械发射** 管线的扩展，而不是引入另一套设计器、坐标 DSL 或 AI 直接改写 PPTX 的路径。最小破坏方案是：在 Markdown 解析完成后、现有 `build_deck_plan()` 之前，加入一个仅含允许语义的 `VisualPlan`；planner 将它和既有 logical document 一起投影成不可变的物理页字段；emitter 继续只消费 `PhysicalDeckPlan`，按 manifest 子区域创建原生可编辑形状。

这一路径保留现有的强约束：作者不能控制坐标、字体、颜色、裁切或动画；视觉选择不能在 emitter 中临时决定；分页不会因 `python-pptx` 对象创建、图片元数据或本机字体而改变。现有 `table`、`gallery`、`timeline` 已证明了“manifest 子区域 + 原生 table/picture/text/group”的实现模式，v1.20 应复用并泛化它，而不是引入 SVG 贴图、整页 raster 截图或自由绘图 JSON。

## 当前可复用骨架

| 层 | 当前职责 | v1.20 的处理原则 |
|---|---|---|
| Markdown parser | 只产生 source-located 逻辑内容，禁止样式/坐标控制 | 只增加受控 `visual` 语义；不得开放任意 attributes 或 raw HTML |
| Manifest | 11 个 layout、slot、EMU 几何、文本预算、子区域与主题所有权 | 追加 layout/variant 注册表和每类 object 的 manifest-owned subregions |
| `pptx_model.py` | frozen dataclass 的 `BlockFragment`、`PhysicalSlide`、`PhysicalDeckPlan` | 把选择后的 visual variant、对象语义、冻结容量/媒体 hash 写入物理计划，而非让 emitter 推断 |
| `pptx_paginate.py` | CJK-aware 测量、语义切分、logical→physical mapping | 增加 visual object 的确定性容量与切分；视觉选择必须早于并参与分页 |
| `pptx_emit.py` | 仅发射 immutable plan，明确不含 pagination | 按 frozen object spec 调 `pptx_objects.py`；不得重新选择 variant、重新分页或自动缩字 |
| `pptx_objects.py` | 由 manifest geometry 创建原生表格、图片、文本、组、时间线 | 为新增 layout 增加窄小 helper；shape name 保持稳定、可 reopened inspection |
| verify | 8/6/21 固定 registry，重开 OOXML 取证 | 增加固定 v1.20 子门与 raw-plan→OOXML 对照，不用截图或 producer 常量作 PASS |

已存在的直接锚点是 `pptx_paginate.build_deck_plan()`、`pptx_emit.emit_deck()`、`pptx_objects.add_table()`、`add_gallery_card()` 与 `add_timeline()`。它们说明现有边界已经适配 native editable objects；不需要替换 renderer。

## 推荐的 VisualPlan

### 受控输入面

VisualPlan 不应成为可独立发布的公开 JSON sidecar，也不能让 Markdown 写入像素值。推荐把它定义为 parser 内部的、source-located dataclass/projection：

```text
VisualIntent
  kind: hero-evidence | annotated-image | process-overlay | kpi-evidence | gallery
  source_block_ids: stable authored block/index references
  assets: validated logical media references only
  facts: bounded title/label/value/unit/annotation/process-step semantics
  variant: optional allowlisted manifest id; otherwise planner deterministic selection
```

Markdown 至多声明 `layout="hero-evidence"` 这类 allowlisted 语义，以及严格数量/结构的正文、图片和表格；它不能给 `VisualIntent` 传 `x/y/width/height/crop/font/color/z-index/animation`。若采用自动 variant，选择函数必须是纯函数，只依赖冻结的逻辑内容、manifest version/hash 和明确规则；其结果连同理由/容量进入 PhysicalDeckPlan，不能在 render 时受本机环境影响。

### 新语义 layout 的最小首批集合

1. **`hero-evidence`**：一张主要图片承载场景，标题、关键结论、可选证据标签为 native text/shape。适合封面后的事实主张，不能把结论烧进图片。
2. **`annotated-image`**：一张 contain 图片 + 有上限的编号标注、引线和说明文本框；编号/说明为原生可编辑对象，标注只能锚定 manifest 定义的有限锚区，不能作者任意坐标。
3. **`process-overlay`**：2–6 步的原生节点、连接线、编号、短标签；步骤来自严格 Markdown 表格或列表，必须先做容量切分。
4. **`kpi-evidence`**：2–4 个原生数字卡、单位、标签与可选脚注；数值保持文本，不生成不可编辑图像或联网图表。

`gallery` 是既有语义，应作为新 VisualPlan 的对照实现，不重新设计。首批不做自由图表、SmartArt、动画、SVG path、任意图层和在线图片检索。

### 物理计划字段

建议在 `PhysicalSlide` 增加一个 immutable `visual_objects` 序列（或等价 frozen fragment），每一项至少包含：`kind`、稳定 `object_id`、manifest `region_id/variant_id`、冻结文本、已验证 media digest/bytes reference、源行、占用的 capacity units。对于跨页对象，planner 显式生成多个 object spec 和 physical index；emitter 不得对同一 source 再切分。

将 `visual_objects` 纳入 `PhysicalDeckPlan.to_projection()`，让验证从原始 plan 重算：每个 logical source 的对象数量、顺序、所占页、variant、可见文本和媒体绑定。这比在 emitter 中临时读 Markdown 或 manifest 决策更容易证明确定性。

## Pagination 与确定性

新 layout 的分页原则应沿用当前“先语义分割、后 immutable physical plan”的决定：

- 每个 visual kind 在 manifest 中声明 `max_items_per_page`、文本预算、子区域、分割策略和 continuation 行为；不要靠 `python-pptx` autofit、图片实际尺寸或 PowerPoint 渲染结果决定是否溢出。
- `annotated-image` 以标注为原子：图、编号、引线、说明不得拆散；超过容量时将标注按稳定源码顺序分组，主图可按冻结规则重复。
- `process-overlay` 按完整步骤原子分页；超过 6 步等容量时分为多个物理页，并保持标题/notes 和 logical mapping。
- `kpi-evidence` 卡片按固定 2/3/4 preset 分组，数值+单位+标签不可拆；长标签只能按该 slot 的 shrink/paginate/fail policy 处理。
- 视觉布局不参加“美观随机平衡”。如果需要左右均衡，使用可复算的容量向量、固定 tie-break（源码 index、再 object id），并在 evidence 导出选择结果。

媒体仍须走现有单次 descriptor-read、bounded bytes、校验后同 payload `add_picture` 的链路。图片 natural dimensions 只能用于已定义的 contain 计算；不得读取路径两次、不得以 EXIF/联网结果改变分页。

## Native editable objects 规则

- 文本、数字、标签、标注、步骤、连接线与表格全部用 PPTX 原生 text box/shape/connector/table；`school-pptx:<kind>:<stable-id>` 命名约定应扩展到每个新增对象和组。
- 主要图片使用现有 contain 路径；卡片背景、线条、圆点和标注均从 manifest token/geometry 构建。主题变化只能由 manifest token 驱动，不能改变事实、对象数量或文档语义。
- 可将同一语义单元 group 化（类似 gallery card / timeline node），但验证必须同时检查 group 与子对象，且编辑后可选择/改写文本、数值和图注。
- 不将“可编辑”误写为“可随意重排仍自动适配”。用户手工修改后的几何不由 renderer 回收；下一次 render 始终由 canonical Markdown + manifest 重建。

## 不可触碰的安全与确定性边界

1. **Markdown 只写语义。** 不开放 coordinates、fonts、colors、crop、footer、style、raw HTML、通用 attributes、动画或任意 object JSON；这会破坏模板所有权和审阅可预测性。
2. **Manifest 是所有 geometry 的唯一事实源。** 禁止在 planner/emitter 复制 EMU、字号、色值或预设；任何新增 region 必须通过 template-report 的 geometry/预算/边界检查。
3. **Emitter 不得分页。** `emit_deck()` 只能机械消费冻结 PhysicalDeckPlan；禁止 autofit、重新测量、根据 add_picture 结果换 layout、或从 Markdown 重解析。
4. **离线且 descriptor-safe。** 不联网拉图/图标/字体；不以 CWD 搜字体；媒体、模板和交付仍使用 no-follow、bounded read、hash/identity 绑定和 staged validation/publication。
5. **PASS 必须 fresh 且可重算。** 不接受固定计数、截图比对、肉眼“看起来不错”或旧 evidence；失败的 best-effort deck 只能留在 owned work evidence，不能作为 current 成功投递。
6. **不扩张公开交付物。** 成功 delivery 仍仅为同 stem Markdown + PPTX + 已确认 `assets/...`；VisualPlan/projection/diagnostics 仅在 caller-owned verification workdir。

## 推荐分期与依赖

### Phase A：VisualPlan 契约与模板注册

**目标：** 先冻结语义输入、manifest schema 和四类 layout 的子区域/预算，尚不改 emitter。  
**依赖：** 现有 Markdown allowlist、template-report、controlled `.pptx`。  
**实现：** 新 layout 必须有 manifest layout part 或明确 renderer-owned-native-shapes mapping；扩展 parser 的 layout shape 验证、source locations、overflow evidence；template-report 校验 region containment/non-overlap/presets/slot budget。  
**验收：** 旧 11 layout fixture 不变；每个新 layout 有合法、超量、未知 attribute、禁用坐标和缺图 negative case；manifest drift 必须 fail closed。

### Phase B：纯 planner 与冻结分页

**目标：** VisualIntent 在 `build_deck_plan()` 前得到确定性选择，生成可投影的 visual physical plans。  
**依赖：** Phase A 的 schema、容量规则。  
**实现：** 只在 `pptx_paginate.py`/model 增加 pure planner；将 variant、capacity vector、logical→physical mapping、notes intent、媒体指纹绑定写入 plan。  
**验收：** 相同 canonical bytes + manifest 产生 byte-for-byte 等值 projection；重排无关输入不得改变选择；超量样例断言每个对象完整、顺序稳定、无重叠和无 emitter-time split。

### Phase C：原生对象发射与 OOXML 重开检查

**目标：** 按冻结 plan 创建可编辑 image/shape/text/line/group/table，不改变分页。  
**依赖：** Phase B 的 PhysicalDeckPlan schema。  
**实现：** 每类对象一个窄 helper，统一 stable naming；`pptx_emit.py` 按 object kind 分发并拒绝未知 kind；将新增对象加入结构 inspection。  
**验收：** reopen PPTX 后检查 object type/name/text/count/geometry/relationships；修改计划中的 variant、物理页或文本时，AST/mutation guard 必须使验证失败；人工 UAT 验证在 WPS/PowerPoint 内可选中、编辑并保存原生对象。

### Phase D：验证、回归与受控样张/UAT

**目标：** 将视觉增强接入固定验证权威并证明不破坏 clean delivery。  
**依赖：** Phase C。  
**实现：** 固定 registry 新增 visual contract/planner/native-object/determinism/negative gates，且 required==called、零 dynamic skip；为代表性样张保留 source + verification work evidence，不把截图当自动 PASS。  
**验收：** 旧 8/6/21 仍全绿且注册表变更明确版本化；delivery transaction、媒体 TOCTOU、template reader 和 no-network 测试均覆盖新增 layout；独立人工 UAT 分别记录视觉、可编辑性、notes、保存重开结果。

## 主要风险与缓解

| 风险 | 后果 | 缓解/检测 |
|---|---|---|
| VisualPlan 变成隐性坐标 DSL | 模板失去控制、审阅与跨 runtime 不一致 | 只存 allowlisted semantic fields；schema negative tests 拒绝 geometry/style keys |
| planner/emitter 双重决策 | pagination false-green、输出不可复现 | emitter 无分页/variant selection；plan projection 与 reopened OOXML 双向比对 |
| 复杂视觉以单张图片交付 | 数字/标注不可编辑，无法验收 | 将所有信息层做原生 objects；图片只承担场景/证据 |
| 自动选择受环境影响 | 相同输入生成不同 deck | pure function + frozen manifest hash + stable tie-break；禁止网络、字体/CWD discovery |
| 新对象绕过媒体安全路径 | 路径替换、解码 bomb、泄露路径 | 复用 descriptor-bound validated bytes 和 allowlisted stable errors |
| 添加验证但未接入权威 | 局部 PASS 掩盖回归 | 固定 registry、required/called equality、raw evidence recomputation、mutation guards |
| 扩张 public artifacts | 污染 clean delivery、泄露 diagnostics | VisualPlan/evidence 只写 caller-owned workdir；delivery allowlist 保持不变 |
