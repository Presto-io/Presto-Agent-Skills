# v1.20 `school-pptx` 视觉与 UAT 调研

**范围：** 验证策略、完整夹具、视觉多样性、主体风格稳定、原生可编辑性与媒体安全。  
**结论置信度：高。** 结论来自当前 `school-pptx` 的已实现验证器、完整 Markdown/媒体夹具、模板 manifest 和既有 hash-bound PowerPoint/WPS UAT；不把旧里程碑的 PASS 外推到 v1.20 新布局。

## 已有基础与缺口

v1.17 已有很强的底座：public `verify` 固定执行 8 个顶层门、6 个负例和嵌套的 21 个渲染门；会重开 OOXML，核验 notes、native table、editable code、timeline/gallery group、媒体关系与 `whole_slide_picture_count == 0`。人工 UAT 已明确禁止由自动化、截图、PDF、缩略图或 OOXML reopen 替代，并要求在 Microsoft PowerPoint 或 WPS Presentation 中实际编辑文本、表格、代码和组对象。

但该套夹具只证明旧 11 类布局的正确性。v1.20 新增的 `hero-evidence`、`annotated-image`、`process-overlay`、`kpi-evidence` 若仅加入一张“漂亮样张”或截图比较，既不能证明语义分流真实发生，也不能证明对象仍可编辑。验收必须从“视觉看起来不同”落实为可重算的布局使用、对象类型、媒体绑定和真人编辑行为。

## 可测 Requirement 候选

| ID | Requirement 候选 | 自动验证证据 | PowerPoint/WPS UAT 证据 |
|---|---|---|---|
| `VIS-01` | `standard-school` 继续是唯一 theme；新布局只使用 manifest/template 拥有的字体、颜色、背景、页脚、装饰和几何，Markdown 只能表达语义内容。 | manifest/renderer 断言 theme、slot、色彩角色和几何来源；负例拒绝 Markdown 坐标、字体、颜色、裁剪、raw OOXML。 | 跨封面、旧布局和四种新布局抽查字体角色、页脚、背景与对比；任何主体样式漂移为 FAIL。 |
| `VIS-02` | 完整 fixture 必须覆盖旧 11 布局及四种新布局，并为每种新布局提供至少一个适配的语义内容；不得把同一张图文页换标题后充数。 | 从 source logical slide、冻结 PhysicalDeckPlan 与 reopened PPTX 重算 layout 覆盖、每布局物理页数和新布局内容类型。 | 逐页查看新布局，确认其信息层与内容语义匹配，而非模板空壳。 |
| `VIS-03` | 新布局使用显式、受控的语义选择规则；同一 fixture 至少出现四种不同的视觉构图，且常规图文页不承担 hero、标注、流程和 KPI 的语义。 | 由 Markdown block kind → layout mapping 建立固定断言；检查四种新布局均有非空独有对象集合，而非只复制 `image-text` 的 picture/text。 | 抽查每类构图的阅读路径、信息优先级、留白和标题/主体/证据层是否清楚。 |
| `VIS-04` | 所有新信息层均使用原生 PPTX 对象：文字为 text shape，数字/KPI 为可编辑文字与可编辑形状，箭头/标注/流程为可编辑 shape/group；禁止任何整页截图和把信息层烘焙进图片。 | OOXML/reopen 检查命名对象、shape type、group 成员、text 和 picture 几何；`whole_slide_picture_count == 0` 保持为硬门，并新增新布局对象清单。 | 选择每种新布局，编辑一段文字、一个数值、一个标注、一个流程节点；对 group 执行移动、ungroup、成员编辑/替换和必要的 regroup。 |
| `VIS-05` | 媒体严格按语义布局的受控 slot contain 放置，保留比例且默认不裁剪；图注、标注、数据卡和流程文字不写入媒体像素。 | 对每个 picture 记录 source hash、relationship、crop/contain 几何、slot id；媒体由一次 descriptor-read 校验后同一 payload 进入 `add_picture`，缺失/解码失败保持非零。 | 检查横图、竖图和极端比例图无拉伸、无意外裁切；确认标注文字可单独选中编辑。 |
| `VIS-06` | 为 hero、标注图、流程覆盖和 KPI 证据增加边界夹具：空/缺失媒体、超长标题、超长标注、过多步骤、过多 KPI、极端图片比例；不安全或不可布局输入 fail closed，允许的 missing-media 仅产生局部可编辑 placeholder 并使 render 非零。 | 固定负例 registry，断言稳定错误码、非零退出、无 traceback、无 current false-success；对允许 best-effort 断言 placeholder 仅占受影响 slot 且不污染其他页。 | 仅对 best-effort placeholder 样张，检查 placeholder 可编辑、不会遮挡主体，也不会被误认为真实媒体。 |

## 推荐 fixture 矩阵

`school-pptx-full.md` 应继续作为唯一的 Markdown-first 完整 fixture；新增内容应使用真实教学语义（例如实训设备、工序安全、诊断流程、产线 KPI），而不是为凑覆盖而填的 Lorem Ipsum。媒体保留 skill-local、可审计的小型 PNG/JPEG；任何新原图都需明确许可/来源，并纳入 hash 与大小上限检查。

| Fixture 情形 | 目的 | 必测点 |
|---|---|---|
| `hero-evidence` | 课程/任务的主证据图与少量关键事实 | 主图 contain、标题可读、证据文字独立编辑、无整页图片。 |
| `annotated-image` | 设备图上的安全区、组件、观察点 | 标注是原生 shape/text，可移动和编辑；不会覆盖媒体外的页脚或标题。 |
| `process-overlay` | 工序、诊断或操作流程 | 流程节点和箭头为可编辑对象；步骤过多时按固定规则拆页而不缩至不可读。 |
| `kpi-evidence` | 产能、合格率、能耗等定量事实 | 数字、标签、单位、趋势/比较形状可编辑；无图像化图表替身。 |
| `media-boundary` | 横/竖/极端宽高比、缺失、损坏或超限媒体 | contain/crop、稳定错误码、局部 placeholder 和 non-zero best-effort 语义。 |
| `regression-full` | 旧 11 布局 + 4 新布局的完整串联 | layout 覆盖、章节节奏、分页、notes、native table/code 和新对象类型全部重算。 |

夹具不是视觉基准截图。若需预览图供人工快速定位，应在 caller-owned verification workdir 生成，并标记为非权威诊断；不可进入正常 Markdown + PPTX 两件套交付，也不可作为 hash/UAT 的替代物。

## 推荐验证分层

1. **作者级 contract/负例：** 校验新 Markdown 语义、布局允许集、媒体相对路径和拒绝 raw visual override；新增布局必须有明确 block-to-layout mapping，不能靠关键词猜测。
2. **渲染级 frozen-plan/OOXML：** 从完整 fixture 重建 plan 并 reopen PPTX，验证新布局覆盖、slot 几何、shape/group 类型、文本、媒体 relationship/hash、caption/annotation/KPI/flow 对象和不存在 whole-slide picture。
3. **公共 verify aggregate：** 把上述检查加入固定 registry；required/called 顺序和集合精确相等，零动态 skip，证据由本次 artifact 重算。它是自动 PASS 的唯一来源，但只表示结构 PASS。
4. **真人 viewer UAT：** 绑定同次 public verify 的 canonical Markdown/PPTX hash。PowerPoint 或 WPS 中逐项观察、编辑并撤销；截图仅可帮助复现某页，不可替代操作记录。新 hash、viewer FAIL/BLOCKED 或 current verify failed 都使 UAT 失效。

## UAT 新增检查项候选

保留 `UAT-V01..06` 和 `UAT-I01..04` 作为回归，新增以下项目而不是替换旧项：

| ID | 人工操作与通过条件 |
|---|---|
| `UAT-V07` | 连续浏览完整 fixture：hero、标注图、流程覆盖、KPI 证据各至少一页，构图和信息层显著不同，但字体、色彩、页脚、留白与学校主体风格一致。 |
| `UAT-V08` | 逐一检查横图、竖图、极端比例图，以及可适用的缺失媒体 placeholder：无拉伸、意外裁切、遮挡或把标注烘焙进图片。 |
| `UAT-I05` | 在标注图中移动一个标注、编辑其文字并撤销；图片、标题、页脚和其他标注保持稳定。 |
| `UAT-I06` | 在流程覆盖页移动并 ungroup 一个步骤组，修改节点和箭头，再撤销/重新组合；没有透明遮罩、锁死对象或无法选中的成员。 |
| `UAT-I07` | 在 KPI 页编辑数值、单位、标签和趋势/比较形状中的文字，再撤销；对象保持原生可编辑而非图片。 |

每项记录 `ID | Result | Physical slides / objects | Human observation | Evidence reference`。全项 PASS 才能成为 v1.20 人工通过；第二 viewer 的记录必须独立，不能覆盖第一 viewer 的 FAIL。

## 主要风险与缓解

| 风险 | 后果 | 缓解/验收边界 |
|---|---|---|
| 用不同图片或截图制造“多样性” | 视觉看似丰富，实际阅读路径、原生编辑性和语义映射未提升。 | 以新 layout 覆盖、独有 native object 集和真人编辑动作作为通过依据；截图禁止成为 PASS 证据。 |
| 新布局暗中允许 Markdown 视觉控制 | `standard-school` 主体风格碎片化，后续不可维护。 | manifest 拥有所有视觉 token；contract 负例拒绝坐标、色彩、字体、crop 和 raw OOXML。 |
| 图上标注/流程/KPI 被合成成位图 | 破坏 PPTX 的核心可编辑价值。 | OOXML shape-type/命名对象检查 + viewer 中实际编辑、ungroup 与撤销。 |
| 新夹具只覆盖理想横图和短文 | 实际素材引发裁切、遮挡、溢出或不可读缩小。 | 纳入竖图、极端比例、缺失/损坏媒体、长文本/长标注/过多步骤和 KPI 的边界案例。 |
| 自动结构 PASS 被误写成真人视觉 PASS | 跨 viewer 的编辑、字体替换、选中/组合问题漏检。 | evidence 明确区分 automated PASS 与 UAT；UAT 只由真人填写并 hash 绑定；任何 PENDING/BLOCKED 不能接受。 |
| PowerPoint 与 WPS 的 group/字体行为不同 | 一端可编辑，另一端出现改版或无法操作。 | 最低要求一个合格 viewer 完整通过；若交付目标包含两者，则分别执行独立矩阵并记录 viewer-specific gap，不能互相覆盖。 |
| 预览/导出链引入平台依赖或泄漏进交付 | 验证不稳定，正常交付被 sidecar 污染。 | 预览仅可选、workdir-owned、非 gate；正式交付仍严格为已审 Markdown + PPTX + 已确认资产。 |

## 路线图含义

先锁定 **受控视觉计划与 fixture/媒体边界**，随后实现 **新布局的 native object renderer 与冻结结构验证**，最后执行 **完整 aggregate 与 hash-bound PowerPoint/WPS UAT**。不能先做样张截图或只实现新布局再补安全/编辑验证，因为那会把最难回收的“视觉丰富但不可编辑、不可复验”债务推入后期。

## 需在阶段调研时确认的点

- 新布局具体 Markdown block grammar 和选择优先级需要在设计阶段锁定；本调研只定义“语义映射、非坐标控制”的约束。
- 媒体许可、单文件/总量上限和允许格式应以实际将纳入的图片资产确认，不能从当前 PNG fixture 假设通用阈值。
- 若目标市场要求 PowerPoint 与 WPS 双支持，应把“双 viewer 都通过”写成 requirement；否则应明确最小支持 viewer，避免把单 viewer PASS 描述为跨 viewer 兼容性证明。
