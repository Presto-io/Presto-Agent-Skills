# v1.20 `school-pptx` 视觉增强调研综合

**里程碑：** v1.20 School PPTX Visual Enrichment  
**调研日期：** 2026-07-23  
**总体置信度：** 高（基于当前 `school-pptx` 契约、模板、渲染器、验证器与既有 hash-bound UAT；新布局尚未实现或做真人验收）

## 执行结论

v1.20 是受控模板 PPTX 渲染器的视觉表达增强，不是引入另一套自由设计工具。推荐保留既有 Markdown-first 流程，并把视觉决策收敛为内部、确定性的 `VisualPlan`：经审阅的 Markdown 先形成逻辑文档，再连同 manifest 的固定规则投影为不可变 `PhysicalDeckPlan`，最后由 emitter 机械生成原生 PPTX 对象。图片只作为现场、设备、作品或成果的证据层；所有结论、数字、标注、流程、图注和表格都必须是 PowerPoint/WPS 中可编辑的原生对象。

能力应围绕四种有明确教学语义的构图推进：`hero-evidence`、`annotated-image`、`process-overlay`、`kpi-evidence`，并低风险改良既有 `gallery` 预设。所有几何、颜色、字体、裁切和层级由唯一主题 `standard-school` 的 manifest 拥有；Markdown 只表达受限布局语义、本地媒体和结构化事实。这样既能摆脱重复的普通图文页，也不会牺牲学校主体样式、离线性、可编辑交付或可复验分页。

最大风险不是“看起来不够丰富”，而是为了丰富视觉而把信息烘焙进图片、让 emitter 临时排版、或把自动结构检查误写为真人视觉通过。实施必须先冻结语义和容量，再冻结物理计划，最后发射与验证；每一步都应 fail closed，并将真人 PowerPoint/WPS 操作 UAT 与自动 PASS 明确分开。

## 推荐能力与明确边界

### 应交付的能力

| 能力 | 推荐实现 | 不可变边界 |
|---|---|---|
| `hero-evidence` | 主图使用已校验的本地媒体 `contain` 放置；标题、2–3 个 KPI、说明和图注为原生对象。 | 不使用 full-bleed 或 `slice` 裁切；图片内不写事实文字。 |
| `annotated-image` | 一张证据图配有限编号、引线和说明；标注只能落在 manifest 定义的有限锚区。 | 标注关系必须能从受限逻辑内容无歧义派生；否则延后，不开放任意坐标。 |
| `process-overlay` | 2–6 个原生节点、连接线、序号和短标签，复用现有时间线/分组模式。 | 步骤按原子分页，不能靠缩字或渲染期重排塞入一页。 |
| `kpi-evidence` | 2/3/4 项固定预设的原生数字卡、单位、标签与可选脚注。 | 数字和图表信息不可图像化；不得引入任意 SVG 图表。 |
| `evidence-gallery` | 按 1–4 张图片选择 manifest 固定几何和一致图注带。 | 仅调整受控 preset，不由 Markdown 决定拼贴位置。 |
| 确定性视觉计划 | 将 variant、对象角色、容量、源行、媒体 digest 与 logical→physical mapping 冻结进 `PhysicalDeckPlan`。 | emitter 不得重新选择 variant、分页、测量或自动缩字。 |

### 明确排除项

- 不接入 PPT Master 的自由 SVG/OOXML 追加工作流，不以其替换 `school-pptx` renderer。
- 不提供 Markdown 控制坐标、尺寸、字体、颜色、背景、裁切、`z-index`、动画、raw HTML/OOXML 或任意样式属性。
- 不联网搜图、下载图标、生成 AI 图片、运行时下载字体或按 CWD 搜索资源；只使用已验证的本地媒体。
- 不使用整页截图、扁平位图、复杂滤镜、蒙版、玻璃拟态、自由 path、SmartArt 或动画来伪造复杂视觉。
- 不改变 `standard-school` 的主题、标题、页脚、结束页、模板装饰、默认 `contain` 图片策略或成功交付物边界。
- 不把 `VisualPlan`、预览、诊断、截图或验证 sidecar 加入正常 Markdown + PPTX + 已确认资产的公开交付。

## 架构与依赖

```text
已审阅 Markdown + 已验证本地媒体
  -> canonical logical document / VisualIntent
  -> 纯函数 planner + manifest hash
  -> frozen PhysicalDeckPlan（VisualPlan 投影、容量、媒体绑定）
  -> mechanical emitter
  -> 原生 picture / text / shape / connector / group / table
  -> 自动结构验证 + hash-bound PowerPoint/WPS 真人 UAT
```

`VisualIntent` 只含 allowlist 语义、稳定源块引用、已验证媒体、受限事实和可选 manifest variant；`VisualPlan` 是其确定性投影，而非新的公开数据格式。所有新增 region、预设、token 和文字预算必须位于 manifest；planner/emitter 不得复制 EMU、字号、色值或布局常量。

## 建议分期

### Phase 1：视觉合同、样张与模板注册

**依赖：** 既有 Markdown allowlist、`standard-school` manifest、`template-report`。  
**交付：** 仓库外 6 页样张基线（四种新构图、改良 gallery、既有基准页）；manifest 的 layout/variant、subregion、容量和 non-overlap 规则；受限 Markdown 语义与负例。  
**原因：** 先用真实本地教学媒体验证构图目的，再固化模板契约，避免把未经审阅的视觉猜测编码进 renderer。  
**必须避免：** 用样张截图替代结构契约；用自由 attributes 解决 `annotated-image` 的语义歧义；改变主题或图片 `contain`。

### Phase 2：纯 planner 与冻结物理计划

**依赖：** Phase 1 的 manifest schema、数量上限和分割策略。  
**交付：** `VisualIntent`/`visual_objects` 的 immutable model；确定性 variant 选择、容量向量、逻辑到物理映射、媒体 hash 和可重算 projection。  
**原因：** 视觉选择必须在 emitter 前参与分页，才能防止同一输入随环境或对象创建顺序产生不同 deck。  
**必须避免：** 根据图片元数据、字体、网络或渲染期结果重新平衡版式；跨页拆散标注、流程步骤或 KPI 卡。

### Phase 3：原生对象发射与自动结构验收

**依赖：** Phase 2 的 frozen plan。  
**交付：** 每类新增对象的窄 helper、稳定 `school-pptx:<kind>:<id>` 命名、reopen OOXML 检查和 plan→PPTX 对照。  
**原因：** 原生可编辑是本技能的核心交付价值，必须由对象类型、文本、group 成员、关系和 geometry 证明，而非渲染截图证明。  
**必须避免：** 让 emitter 做分页/variant 决策；把文字、标注、流程或数值烧进图片；绕过 descriptor-bound 媒体读取。

### Phase 4：完整夹具、聚合验证与真人 UAT

**依赖：** Phase 3 的可重开原生对象。  
**交付：** 唯一完整 Markdown fixture 覆盖旧 11 布局和四种新布局；固定 aggregate registry、边界媒体/溢出负例、hash-bound UAT 表单和完成记录。  
**原因：** 新布局的正确性既需回归旧能力，也需证明视觉多样性、可编辑性和跨 viewer 实操，不可后补。  
**必须避免：** 自动 PASS 冒充视觉 PASS；动态 skip、旧 evidence、预览图或 PDF 作为通过依据；将失败的 best-effort 输出发布为 current 成功交付。

### 分期顺序理由

- 样张只用于审定构图语言，模板注册才是正式实现入口；先实现 renderer 会导致不稳定的布局返工。
- planner 是发射器的唯一上游，故必须在原生对象 helper 前完成，确保分页和对象角色可复算。
- 完整 fixture、固定验证 registry 和真人 UAT 放在能力闭环末尾，但其 requirement 与负例应从 Phase 1 同步设计。
- `gallery` preset 改良可随 Phase 1–3 合入；`annotated-image` 在标注语义无稳定 grammar 时必须从首批范围剔除，而非放宽 Markdown。

## 风险、缓解与验收策略

| 风险 | 防线 | 通过证据 |
|---|---|---|
| 信息层被烘焙进图片 | 图片仅承载证据；文字、数字、标注、线和表格均为 native objects。 | reopen OOXML 的对象类型/名称/文本检查；viewer 内编辑、移动、ungroup、撤销。 |
| VisualPlan 演变成坐标 DSL | 只允许受限语义字段；manifest 作为所有 geometry 与主题 token 的唯一事实源。 | contract 负例拒绝 geometry/style keys；`template-report` 校验 region、预算、包含关系和重叠。 |
| planner 与 emitter 双重决策 | planner 冻结 variant、容量、物理页和媒体绑定；emitter 仅按计划分发。 | 相同 canonical bytes + manifest 产生相同 projection；mutation guard 与 plan→OOXML 对照。 |
| 媒体造成安全或可复现性问题 | 单次 descriptor-read、bounded bytes、hash/identity 绑定、允许格式与稳定错误。 | 缺失、损坏、超限、极端比例媒体负例；非零状态与局部可编辑 placeholder（如契约允许）。 |
| “视觉多样性”只靠换图或截图 | 用布局覆盖、独有对象集合、语义映射和阅读路径审阅定义多样性。 | 完整 fixture 四种新布局均有匹配内容；不以像素 diff、AI 评分或缩略图为 PASS。 |
| 自动结构 PASS 覆盖真人问题 | 自动和人工证据分层，UAT 与同次 Markdown/PPTX SHA-256 绑定。 | 至少一位实际操作 PowerPoint 或 WPS 的测试者记录 viewer/版本/OS/时间/对象页/观察；PENDING、FAIL、BLOCKED 或 hash 变化均阻止接受。 |

## 可追溯需求候选

| ID | 候选需求 | 主要验证 |
|---|---|---|
| `VIS-01` | `standard-school` 是唯一主题，模板拥有全部样式和几何，Markdown 仅能表达语义。 | manifest/contract 负例 + viewer 主体风格抽查。 |
| `VIS-02` | 完整 fixture 覆盖旧 11 布局与四种新布局，每种新布局使用真实、适配的教学语义。 | logical source、frozen plan、reopen PPTX 三向重算 + 逐页 UAT。 |
| `VIS-03` | 四种新构图均有显式语义映射与非空独有 native object 集，不只是改名的 `image-text`。 | block→layout mapping、对象角色检查 + 阅读路径审阅。 |
| `VIS-04` | 新信息层均为原生可编辑对象，整页截图和信息层烘焙图片为硬失败。 | OOXML/reopen `p:pic`、`p:sp`、`p:grpSp`、`a:tbl` 检查 + 编辑/ungroup UAT。 |
| `VIS-05` | 所有媒体经受控 slot 的 `contain` 策略放置；图注、标注、流程与 KPI 文本不写入媒体像素。 | hash/relationship/slot/crop 检查 + 横竖和极端比例媒体 UAT。 |
| `VIS-06` | 空/缺失/非法媒体、超长文案、过多标注/步骤/KPI 必须稳定 fail closed 或按既有契约局部 best-effort 且非零。 | 固定负例 registry、稳定错误码、无 traceback、无 false-success。 |
| `VIS-07` | 视觉多样性以语义与结构覆盖验收，不以截图、像素评分或随机换图验收。 | deterministic plan、对象/文本/媒体关系证据 + 全 deck 节奏观察。 |
| `VIS-08` | v1.20 UAT 必须是本次 artifact hash 绑定的真实 PowerPoint/WPS 操作记录。 | 自动生成且 lint 的 PENDING 表单 + 人工完成回归和新增 `UAT-V07..08`、`UAT-I05..07`。 |

## 调研旗标与待确认事项

**需要阶段调研：**

- Phase 1：确认新 layout 的具体 Markdown grammar、选择优先级、`annotated-image` 的稳定标注关联，以及拟纳入媒体的许可、格式、单文件/总量上限。
- Phase 4：明确支持承诺是“至少一个 viewer 通过”还是 PowerPoint 与 WPS 均须通过；若宣称双支持，必须分别完成独立 UAT 矩阵。

**可按既有模式执行：**

- Phase 2：冻结 dataclass、CJK 容量切分、stable tie-break、projection 和 deterministic plan 均有明确现有实现锚点。
- Phase 3：原生 table/picture/text/group/timeline 发射、稳定对象命名、OOXML reopen 与固定 registry 扩展均有现成模式。
